## 6. 🚨 보안 감사 및 인증 시스템 전면 복구 (2026-07-21 추가 세션)

### 6.1 발견된 문제
- 실제 운영 사이트는 로컬 서버로 정상 전환되어 있었으나(1~5절), 다음 문제들이 실측으로 확인됨:
  1. **Mixed Content**: 클라이언트 JS가 HTTPS 사이트에서 평문 `http://183.101.105.167:8000` Supabase Kong을 직접 호출 → 브라우저가 차단할 수 있는 구조.
  2. **로그인/딜러 계정 시스템 미작동**: `verify_login`, `admin_upsert_dealer` 등 RPC 함수가 DB에 전혀 존재하지 않았고, `alpine-home.users` 테이블도 비어있었음. 저장소에 남아있던 `supabase-setup.sql`(클라우드 시절 스크립트, `public` 스키마 기준)이 로컬 이관 후 재실행되지 않아 발생. **결과적으로 로그인은 `js/auth.js`에 하드코딩된 평문 비밀번호로만 동작 중이었고, 46개 개별 대리점 계정은 전부 로그인 불가 상태였음.**
  3. **`public` 스키마 중복 테이블 완전 개방**: `public.dealers`/`price_list`/`service_management`에 `anon` 롤이 SELECT/INSERT/UPDATE/DELETE/TRUNCATE 전부 보유. 클라이언트가 스키마 미지정 시 기본으로 이 `public`을 사용하고 있어 누구나 데이터를 파괴할 수 있는 상태였음.
  4. `alpine-home.users`(비밀번호 해시 포함)에도 `anon` SELECT 권한이 열려있었음.
  5. `admin.html`에 클라이언트측 role 체크는 있었으나(`currentUserRole !== 'admin'`), `auth.isLoggedIn()` 체크가 빠져 있었음.

### 6.2 조치 내역
- **HTTPS 엔드포인트 신설**: `https://supabase.alpine-korea.co.kr` (Cloudflare DNS + 로컬 nginx 리버스 프록시, Kong `:8000`으로 연결). `js/auth.js`, `js/supabase-client.js`, `pages/admin.html`의 기본 접속 주소를 이걸로 교체.
- **인증 시스템 재구축** (`scripts/alpine_home_auth_setup.sql`, `alpine-home` 스키마 기준으로 재작성):
  - RPC 함수 8종 신설: `verify_login`, `update_password`, `_is_admin`(내부 헬퍼), `admin_upsert_dealer`, `admin_delete_dealer`, `admin_list_service_admins`, `admin_list_service_records`, `admin_upsert_service_record`, `admin_delete_service_record` — 전부 `SECURITY DEFINER` + pgcrypto bcrypt 검증.
  - `alpine-home.users`에 계정 시드 완료: 공용 6계정 + 개별 대리점 43계정(기존 `supabase-setup.sql` 값 그대로 복원, 비밀번호 대부분 `1234`류로 약함 — 추후 개별 변경 권장).
  - `alpine-home.users` SELECT 및 `public`/`alpine-home` 양쪽의 `dealers`/`price_list`/`service_management` INSERT/UPDATE/DELETE/TRUNCATE를 `anon`/`authenticated`에서 회수(SELECT는 공개 데이터라 유지).
  - 부수 발견 버그 수정: `alpine-home.dealers`/`price_list`/`service_management`의 ID 시퀀스가 대량 마이그레이션 이후 재동기화되지 않아 신규 등록 시 PK 충돌 발생 → `setval`로 재동기화. `alpine-home.service_management`에 `images` 컬럼 누락 → 추가. `cost` 컬럼이 numeric인데 콤마 포함 문자열이 들어오는 문제 → RPC에서 정규식으로 정리 후 캐스팅.
- **클라이언트 코드 전환**:
  - `js/auth.js`: 하드코딩된 평문 비밀번호(`USERS` 객체) 완전 삭제, 모든 Supabase 클라이언트 생성에 `db:{schema:'alpine-home'}` 지정, 로그인 로직을 RPC 단일 경로로 단순화.
  - `js/supabase-client.js`: 스키마 지정 추가, 더 이상 쓰이지 않는 `upsertDealer`/`deleteDealer`(테이블 직접 접근) 삭제.
  - `pages/admin.html`: 스키마 지정 추가, `startAdmin()`에 `auth.isLoggedIn()` 체크 추가, 딜러 저장/삭제 로직을 `admin_upsert_dealer`/`admin_delete_dealer` RPC 단일 호출로 통합(기존 2단계 방식 제거).
  - `js/service-management.js`: AS 기록 조회/저장/삭제를 전부 `admin_list_service_records`/`admin_upsert_service_record`/`admin_delete_service_record` RPC로 전환.
- **검증**: curl로 로그인(정상/오류 비밀번호), 딜러 생성/삭제, 서비스 기록 생성/수정/삭제, 직접 테이블 접근 차단(users/dealers/service_management) 전부 실측 확인 완료.

### 6.3 로컬 브라우저(Playwright) 실사용 테스트로 발견·수정한 추가 버그
로그인 → 관리자 패널 → 서비스 관리 흐름을 실제 브라우저로 구동해 검증하는 과정에서 이번 작업과 무관하게 존재하던 버그도 함께 발견되어 수정함:
- **`DEFAULT_LOCAL_SUPABASE_URL` 중복 선언 충돌**: `js/auth.js`와 `js/supabase-client.js`가 동일한 이름의 최상위 `const`를 선언하고 있어, 두 스크립트를 모두 로드하는 페이지(index.html 등 174개 파일)에서 `SyntaxError`로 두 번째 스크립트 전체가 실행되지 않던 문제. `js/supabase-client.js` 쪽 변수명을 `SC_` 접두사로 변경해 해결.
- **`alpine-home` 전 테이블 ID 시퀀스 불일치**: 대량 마이그레이션 이후 `dealers`, `price_list`, `service_management`, `visitor_logs`, `vehicle_make`, `vehicle_model`, `vehicle_trim`, `oem_speaker`, `pnp_harness`, `partner_board` 시퀀스가 실제 `MAX(id)`보다 뒤처져 있어 신규 등록 시 PK 충돌 발생 — 전체 스캔 후 일괄 재동기화.
- **`visitor_logs` 권한/데이터 오류 3종**: (1) 스키마 전환으로 `alpine-home.visitor_logs`에 anon INSERT 권한이 없던 것 → 부여, (2) `visitor_logs_id_seq`에 USAGE 권한 없던 것 → 부여, (3) `js/auth.js`가 `visit_date`(date 타입)에 `toLocaleString('ko-KR')` 문자열을 그대로 넣어 파싱 실패하던 것 → ISO 날짜로 수정.
- **검증 방법**: Playwright(headless Chromium)로 `alpineaudio` 계정 로그인 → `admin.html` → `service-management.html` 이동, 콘솔 에러 0건 확인.

### 6.4 Storage 버킷 점검 및 수정 (추가 세션)
- `js/service-management.js`가 참조하던 `service-images` 버킷이 실제로 존재하지 않아, AS 사진 첨부 기능이 한 번도 성공한 적이 없었음(업로드 0건). 실제 버킷명 `as-attachments`로 코드 수정.
- `as-attachments`에 RLS 정책이 전혀 없어(anon 완전 차단 상태) `anon` INSERT 전용 정책 추가(`Anon upload for as-attachments`). 삭제/수정 권한은 부여하지 않음 — 버킷 자체가 `public=true`라 읽기는 별도 정책 없이 가능.
- 8개 버킷(defective-photos, checklists, as-attachments, workspace_layouts, manuals, inquiries, portfolio, gallery) 모두 `public=true` — RLS와 무관하게 URL만 알면 파일 열람 가능한 구조(다른 프로젝트도 동일 패턴).

### 6.5 GitHub 토큰 서버측 이전 + Storage 정책 점검 (추가 세션)
- **문제**: `pages/admin.html`(및 `pages/estimate-setup.html`에 별도로 중복 구현된 설정 패널)이 저장소 쓰기 권한이 있는 GitHub PAT를 브라우저 `localStorage`에 평문 저장하고, 브라우저에서 직접 GitHub API를 호출하고 있었음. XSS 발생 시 토큰 탈취 위험.
- **조치**: Postgres `http` 확장(pgsql-http, 동기식 PUT 지원 — `pg_net`은 PUT 미지원이라 부적합해서 교체) 설치 후, `alpine-home.app_secrets` 테이블(RLS, RPC 전용)에 토큰을 서버측에만 저장. `admin_set_github_config`/`admin_github_status`/`admin_github_test_connection`/`admin_github_get_sha`/`admin_github_put_file` RPC 5종 신설(SQL: `scripts/alpine_home_github_proxy.sql`).
- `js/github-client.js`(`GitHubClient` 클래스)의 내부 구현을 브라우저 직접 fetch → RPC 호출로 전면 교체하되 **공개 메서드 시그니처는 그대로 유지**하여, admin.html 내 10여 곳의 `ghClient.uploadFile()`/`commitFile()` 호출부는 코드 수정 없이 그대로 동작하도록 함.
- `js/auth.js`의 GitHub 설정 모달, `pages/estimate-setup.html`의 중복 설정 패널도 서버 저장 방식으로 전환(더 이상 `localStorage.setItem('github_token', ...)` 없음).
- `admin_github_status`는 토큰 값 자체를 반환하지 않는 단순 상태 조회라 관리자 인증 없이 호출 가능하게 설계(페이지 로드마다 비밀번호 프롬프트가 뜨는 걸 방지).
- **검증**: Playwright 브라우저 테스트로 로그인 → admin.html 로드 시 프롬프트 없이 "GitHub Connected" 표시 → 실제 `ghClient.commitFile()` 호출로 관리자 비밀번호 프롬프트 후 진짜 GitHub 커밋 성공 → 테스트 파일 정리까지 전 과정 확인.
- **Storage 정책 점검**: `js/service-management.js`가 존재하지 않는 `service-images` 버킷을 참조해 AS 사진 첨부가 한 번도 성공한 적 없던 버그 발견, 실제 버킷 `as-attachments`로 수정 + `anon` INSERT 전용 정책 추가.
